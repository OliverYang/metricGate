# 为什么"本地 · 0 token · 前后校验"有价值 —— 以及怎么证明

> 本文回答一个问题：在"拼检测覆盖面必输"的前提下，metricgate 该守什么方向，
> 以及**用什么证据**证明这个方向真的有价值。
> 配套：[competitor-research.md](competitor-research.md)（谁有什么）、
> [ab-experiment.md](../evaluations/ab-experiment.md)（闭环价值的实测设计）、
> [evaluation.md](../evaluations/evaluation.md)（引擎侧已测数据）。
> 本文是**方法论层**：该证明什么、按什么顺序、什么会推翻它。

## 1. 先换轴，再谈方向

"拼覆盖范围竞品优势太大"这句话里藏着 **价值 = 检测得更多** 的假设。接受这个
框架就必输：检测是覆盖面游戏，而覆盖面是用语言数、规则数、类型系统买的，
SonarQube / CodeQL 的投入规模不可对抗。

正确动作不是"收窄覆盖"，而是**换一根轴**：

- **横轴（竞品的战场）**：检测覆盖面 / 深度 —— 多语言、多规则、类型与数据流。
- **纵轴（我们的战场）**：**循环内可用性** —— 频率 × 成本 × 确定性。

竞品密集在右下（覆盖广、循环外）；我们只在左上（覆盖窄、循环内）。
右上"覆盖广 + 循环内可用"目前没有产品占据 —— 那是终局，但**入口在左上方**，
不是从右下方挤进去。

## 2. 纵轴为什么是结构性的（不是"还没做"）

| 属性 | 结构性理由 | 竞品为何改不了 |
|---|---|---|
| **频率** | 0 token + 毫秒 ⇒ 可每次编辑都跑，一任务约 50 次 | 竞品一次 PR 跑一次；服务端 / 建库是分钟级 |
| **确定性** | 逐字节一致 ⇒ 可当闸门（exit code / 证据锚 / 审计） | 非确定性检查器结构上不能当门 |
| **本地** | 源码不出机器 ⇒ 内网 / 合规唯一可行，无 seat 计费 | 云端 / SaaS 需要上传代码 |

三者合成一句话：**只有我们能在"单次编辑"的粒度上，给出可机器校验的裁决。**

## 3. 更耐久的一层：知识论证 vs 能力论证

护城河论证里混着两种 claim，衰减性质完全不同：

- **能力论证**（"模型写的代码有幻觉"）：随模型变强**衰减**。今天 P=20%，
  两年后可能 3%。所有这类证据都必须标注模型版本 + 日期，属消耗品。
- **知识论证**（"本仓库的分层规则 / policy / 昨天的签名，不在模型权重里"）：
  **不衰减**。仓库每天变，约束是任意的、私有的、不可预训练的。

持久的卖点因此不是"模型不行"，而是：
**模型不可能知道你的约束，除非有人既便宜又完整地告诉它（生成前），
再既便宜又完整地验它（生成后）。**

"本地 / 0 token / 前后校验"不是三个功能，是**同一件事的三段**。

## 4. 价值怎么分解（以及哪一项没测过）

    价值 ≈ P(模型违反本仓库约束) × 每次拦截省下的返工 − 闸门成本(≈0)

- **P**：唯一没测过的项，也是决定一切的项（乘法左因子）。
- **返工**：省下的 token / 返工轮次 —— 属经济性端点。
- **闸门成本**：≈ 0 token · 毫秒（`evaluation.md` 已测）。

**P ≈ 0 ⇒ 价值 = 0**，无论引擎多正确。所以证明顺序必须是"先测 P"，不是"先跑 A/B"。

## 5. 证据阶梯（从便宜到贵，先证伪再证真）

### R0 引擎正确 —— 已证，但**不证明方向**

`evaluation.md` 的 150/150 检出率证明的是**引擎实现了规则**。一个 100% 正确的
检查器，若模型本就不犯这类错，价值仍是 0。**这一步常被误当成方向验证。**

### R1 基率 P —— 最便宜、最决定性

- 做法：N（≥20）个真实任务裸生成，产物离线过 `metricgate check`，违规
  **按类拆分**计数（banned-api / 分层 / 签名对齐 / 依赖白名单 / 度量阈值）。
- 判据：某类 P ≥ 10–15% ⇒ 该类值得做工具；全类 P ≈ 0 ⇒ 停。
- 推翻：全类 P < 5%。
- 成本：近乎为零，不需要改造 agent 协议。

**✅ 已实测（2026-09，n=22）→ [`evaluation-base-rate.md`](../evaluations/evaluation-base-rate.md)**

| 类别 | P | 读数 |
|---|---:|---|
| C 度量阈值 | 18.2% | 最高产；**全部 error 级来自这里**，集中在"算法自由度"任务 |
| A 禁用 API | 9.1% | **仅当任务把模型推向该行为时触发**；未诱导的 20 个任务为 0/20 |
| B 架构分层 | 4.5% | **自然产生、无诱导，且编译器抓不到** —— 单次价值最高 |
| D 重复 / B 依赖白名单 | 0% | 本任务集未触达，**属设计局限** |
| API 幻觉（编译失败） | **0%** | **负结果**：本实验不支持该主张 |
| **ANY / error 级** | **31.8% / 9.1%** | **方向未被推翻**；9.1% 的任务会被闸门真实拦下 |

**结论**：方向成立，但**投入应重排** —— 价值集中在「度量阈值」与「架构分层」，
而非项目原先最强调的 API 对齐。

**R1b 补充实验（重造率，三臂消融）→ [`evaluation-reuse.md`](../evaluations/evaluation-reuse.md)**

R1 测到 API 幻觉 0/22 后，复盘发现真正原因不是协议不够严苛，而是
**编译器本身就是免费的确定性检查器** —— agent 会 `go build` 并自修，幻觉活不到最后。
于是改测编译器抓不到、又属于"API 对齐"的那一类：**重造既有实现**。

| 臂 | 任务框架 | n | 复用率 | 生成文件 findings |
|---|---|---:|---:|---|
| A | "在包 P 新建函数 `F`" | 10 | **0%** | 15（3 error + 1 clone） |
| B | "我需要 X，放哪你定"（无复用许可） | 5 | **100%** | 0 |
| C | "我需要 X，放哪你定"（允许复用） | 5 | **100%** | 0 |

**三条结论**：
1. **发现不是瓶颈** —— 裸 agent 5/5 找到并复用了既有实现，**包括未导出的跨包内核**
   （`dist.percentile`、`clones.fingerprint`）。⇒ `symbols`/`map`/`facts` 的卖点
   **不能**再是"防幻觉 / 帮你找到既有实现"，其价值必须到别处论证
   （探索的 token 成本、大仓库检索 —— **尚未测量**）。
2. **有效成分是任务框架** —— 把实现钉在指定包/函数名上 ⇒ 100% 重造；
   位置自由 ⇒ 100% 复用。**与是否明确给复用许可无关。**
3. **闸门价值被确认** —— 真实工作里"把代码加到 X 包"是常态，此时重造发生且**编译器不报**，
   只有克隆规则能抓。⇒ "生成前约束"触点的正确表述是
   **"声明模型不会自发遵守的规则"**，而样板应是 R1 的**禁用 API**与**架构分层**，
   **不是"复用"**（有自由度时复用是自发的）。

**R1b 追问："加一句提示是不是就够了？静态分析画蛇添足吗？" → [`evaluation-prompt-vs-gate.md`](../evaluations/evaluation-prompt-vs-gate.md)**

在同一 Arm A 框架下只加**一句**复用提示：

| 臂 | 条件 | 复用率 | findings |
|---|---|---:|---:|
| A | 无提示 | 0% | 15（3 error + 1 clone） |
| **D** | **加一句明确复用提示** | **80%** | **4（2 error）** |
| **E** | **只加"不要重复造轮子"** | **80%** | **5** |

**后续三点（含糊提示 / 探索成本 / SDP 调和）→ [`evaluation-hint-and-cost.md`](../evaluations/evaluation-hint-and-cost.md)**
的结论改写了这张表的读法：两臂总分相同，但**失败的题目不同** ——
Arm E 有一次是"在文件注释里点名了 `internal/repomap`，然后自己重写了一遍 PageRank"。
所以 **80% 不是提示的稳定属性**，而"声称复用 vs 实际复用"只能靠检查区分。
同文还把 Arm D 报的"`arch.Check` 形态不匹配"修正为**适配成本**（Arm E 用 ~60 行适配就复用了）。

提示确实承担了约 80% 的"防重复"工作。**但静态分析不可替代**，因为本次实测中
提示做不到的三件事**全部真实发生**：

1. **验证**：提示是请求不是事实。Arm A 的 agent 点名了原件却仍重写；
   Arm D 的 80% 是 grep 出来的，不是 agent 说的。
2. **暴露结构性不可复用**：剩下 2 个失败**不是不听话** —— `clones.fingerprint`
   **未导出**、`arch.Check` 形态不匹配，是**API 设计**问题。代价：2 个 error 级违规。
   这个信号提示给不出。
3. **抓二阶后果**：照提示复用后，`internal/model` 新引入了对 `selection` 的依赖，
   触发 **`sdp-violation`**（提示说"复用"，架构策略说"稳定的不许依赖不稳定的"）。
   **这是全局属性，任何提示在定义上看不见。**

⇒ 结论：**意图层（提示）与事实层（闸门）互补，不是替代。** 提示让 agent 想做对的事；
闸门证明它做没做到、并暴露提示看不到的全局后果。

### R2 闭环收敛 —— ✅ 已实测（见 evaluation-r2-repair-loop.md）

- **实测结果（2026-09-29）**：配对设计，违规 7/22（基率 31.8% 精确复验）→
  喂 findings+scorecard JSON 后 **7/7 在 ≤3 轮内修复到规约 v1 达标**（6×1 轮 + 1×2 轮），
  修复 token = 生成 token 的 **1.72×**，函数级功能保留 **23/23 零丢失**，LOC 全部增长（拆函数而非删代码）。
- 成本分布不均：度量类违规修复便宜（最低 0.18×）；架构类贵（6.59×，需引端口/组合根的结构性改造）
  ——给支点 1（前置接地）提供成本侧论据：预防架构违规远便宜于事后修复。
- 本轮测的是**修复半环**（post-only，纯 JSON 通道充分性）；pre-only 半环已由 R3 实测（下节），
  both 臂的四臂消融（ab-experiment.md 原设计）仍是开放项，端点按原设计用**每千 token 违规避免数**。
- **R2 前置已完成的四臂（Arm A/D/E，见 evaluation-prompt-vs-gate.md / evaluation-hint-and-cost.md）**：
  提示把重造从 10/10 压到 2–3/10，但残余失败中只有 1 项是“API 不可复用”，
  其余是**适配成本**、**任务框定模糊**、以及**“在注释里点名了既有实现仍然重写”**。
  后者决定了 R2 消融的端点必须包含“声称复用 vs 实际复用”这一项 —— 提示只能给出前者。

### R3 前置接地 —— ✅ 已实测（见 evaluation-r3-grounding.md）

- **实测结果（2026-09-29）**：22 任务生成前注入 `constraints digest`（任务级约束摘要，确定性生成，均价 441 token），
  首过违规 **31.8% → 4.5%**（7→1）；度量类 5/5、禁 API 类 1/1 预防，架构类 U04 未防住（任务诱导的分层张力）。
- **P+B 复合终态 0/22**：唯一漏网由修复回路兜底达标（端口-适配器终态，与 R2 殊途同归）。
- 旗舰证据 U09：模型因 digest 改为复用既有 `hotspots.Compute` 而非自行 shell out——接地改变实现路径，不只是拦截。
- 未决混杂：P 臂生成成本 1.74× 通胀（digest 探索 / 早夭重试 / 单基线方差三因未拆），
  经济端点 0.0014 > 0 但采纳前应补 A 臂同条件复跑。

### R4 经济性反事实 —— 结构性，算术即可

闸门跑 K 次成本 ≈ 0；LLM 评审跑 K 次成本 = K × 每轮 token。K=1 时闸门已胜。
**这只证明"便宜"，不证明"有用"**，必须叠在 R1 / R2 之上。
推翻：不适用（是算术，不是假设）。

### R5 治理 —— 结构性，成本极低

同输入 N 次 + 两台机器 → 哈希相同；据此论证非确定性检查器不能当门。
推翻：出现跨运行 / 跨机器的非逐字节一致输出。

### R6 采纳 —— 最强，且采集最便宜

MCP 本地记日志：工具调用次数 / 每任务分布 / 任务阶段 / findings 修复率。
若 agent 每任务调 `check_code` 8 次、修掉 90% findings ⇒ **行为证据**，
比任何 benchmark 都强：反馈真的被用上、真的可执行。
推翻：每任务调用 < 1 次 ⇒ 通道是理论的。

**装置已就绪**（2026-09-28）：`metricgate-mcp -calllog <file>` 追加 JSONL，
`metricgate calls` 出汇总（按阶段/工具的调用次数、拦截率、收敛率）。
默认关闭、只写本地、不记录源码。接线与指标定义见 [`workflow.md`](../workflow.md) §4。
**这一步只完成了"能测"；上面那句"每任务 8 次"仍然是没有数据的假设**——
真实会话数据是唯一还缺的输入。

## 6. 陷阱

1. **别用 benchmark 分数证明**。一说"我们检出更多"就回到竞品的轴上，然后输。
   要证明的是**循环结果**（收敛 / token / 采纳），不是检测数量。
2. **合成种子证明引擎，不证明方向**。150 个种子是引擎的单元测试。
3. **能力论证会过期**。所有"模型会犯 X 错"的数据都要带模型版本 + 日期。
4. **误报率是反馈的生死线**。基率高但误报也高 ⇒ agent 学会忽略 ⇒ R2 反而变差。
   误报率必须作为**独立门槛指标**，不能并进"违规数"。
5. **"更快"是使能条件，不是价值本身**。快 enables 高频；价值是"高频下省下的返工"。
6. **编译器是免费的确定性检查器（R1b 的教训）**。agent 会 `go build` 并自修，
   所以"编译不过"这类错误**活不到最后** —— 拿它当价值主张必然测出 0。
   判断一个价值主张是否成立，先问：**这件事编译器/linter 已经免费做了吗？**
   只在"编译器抓不到"的地方找价值（度量阈值 / 架构分层 / 组织约定 / 重造）。
7. **任务框架会主导结论**。同一个能力，任务写成"在包 P 新建函数 F"时 100% 重造，
   写成"我需要 X，位置你定"时 100% 复用（R1b）。
   **实验必须同时包含两种框架**，否则会系统性高估或低估工具价值。
8. **"省探索"是个死掉的价值主张（已实测）。** 发现一份既有实现只需 ~4 KB
   （`map` 3.9 KB + 目标文件），看起来比盲读 428 KB 省 99% —— 但 R1b 的 Arm B/C
   在**不用任何工具**的情况下 5/5 复用。**瓶颈从来不是"找不到"。**
   工具真正省下的是**验证成本**（把"我复用了"从自述变成事实）和
   **二阶后果的可见性**（复用改变整张依赖图）。别把省下的字节数当价值。
9. **策略不能惩罚它自己要的行为。** 提示说"复用"，架构策略却把复用引入的依赖边判违规 ——
   agent 最省事的"修法"是把代码抄一份进来，**闸门亲手制造了它要防的重复**。
   所以任何告警的文案必须给出**正确修法并显式排除错误修法**，
   且严重度必须低于 `fail_on`。详见 evaluation-hint-and-cost.md §4。
10. **告警的"含糊"往往是别处漏项的伪装。** 本仓库一条 `sdp-violation`
    （`I=0.50 → I=0.78`）的真实成因是**层声明漏了 6 个包**；
   把 `apisurface` 补进 `core` 后，它立刻变成精确的
   `layer-violation: core may not depend on adapter`。
   **在调参让告警安静之前，先确认它是不是另一条规则的症状。**
