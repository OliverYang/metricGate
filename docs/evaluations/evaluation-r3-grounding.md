# R3 前置接地实验：生成前注入约束摘要，LLM 会不会少犯错（实测）

> 本文是 [`value-proof.md`](../strategy/value-proof.md) 证据阶梯 **R3 级**的实测报告，
> 也是 [`llm-constraint-paradigm.md`](../research/llm-constraint-paradigm.md) **支点 1（前置接地）**的量化验证，
> 与 [`evaluation-r2-repair-loop.md`](evaluation-r2-repair-loop.md)（支点 4）构成"防 + 修"两半。
> 实验设计在动手前预注册于 [`../design/digest-engineering-checklist.md`](../design/digest-engineering-checklist.md)（含可推翻假设）。
>
> 数据采集：2026-09-29，单机，22 任务全量。注入物：`constraints digest` 命令（本轮实现，5 节结构，确定性生成，均价 441 token/任务）。
>
> **判据版本（iter-31 补标）**：本报告的数字采集于判据变更之前，不可按当前工具复现；具体哪把尺子见 [criterion-version-index.md](criterion-version-index.md)。

## 0. 一句话结论

**接地有效，假设 H1 证实**：同一批 22 任务、同一模型、同一沙箱，R1/R2 两次复现的 31.8% 首过违规率，
在生成前注入任务级约束摘要后降到 **1/22 = 4.5%**（相对降幅 85.7%）。
7 个已知违规任务中 **6 个被预防**：度量类 5/5 全防住，禁 API 类 1/1 防住（且实现路径被接地质变——见 §3）；
唯一未防住的是架构类 U04（任务本身诱导跨层），由修复回路兜底（P+B 复合终态 **0/22 违规**）。
经济端点为正（0.0014 违规避免数/千 token），但本轮生成成本出现 1.74× 通胀，归因未决（§5 诚实标注）。

## 1. 协议

预注册设计（2026-09-29 锁定）：

- **Arm P**：22 任务全部带上 digest 再生成。prompt = 原任务文本 + 固定引导语 + 目标包 digest 文本，
  引导语明确"与仓库生效的自动化检查完全一致，代码提交前会被同样的规则机械地检查并拦截"。
- **基线**：R2 Arm A 的 31.8%（7/22），同一模型同批任务在 R1 与 R2 两次独立复现。
- **P+B 复合**：P 臂仍违规的任务接 R2 修复回路协议（findings+scorecard JSON 回灌，≤3 轮，规约 v1 达标判据）。
- **污染对照**：R2 Arm A 与 R3 Arm P 同样携带"模型见过这批任务"的污染，两侧对称，差值可归因于 digest。

执行机制：白名单沙箱逐任务复制（git 基线 aad54e5）、pi headless pin Cliproxyapi/`z-ai/glm-5.3-flash`、
stdin 传 prompt、外部度量 policy（store off）、离线全量 check + zz_eval 过滤 + R1 分类器、
会话 JSONL 逐任务 token 记账。与 R2 唯一的实验变量就是那份 digest。

## 2. Arm P 结果：31.8% → 4.5%

**1/22 违规**。对照 R2 的 7 个违规任务：

| R2 违规任务 | R2 违规类别 | R3 结果 | 证据 |
|---|---|---|---|
| T11 | C 度量（CC 80 / cognitive 121 error） | **防住** | 生成侧即拆小函数：6 函数/122 行（R2 是巨型单体 298 行） |
| U06 | C 度量（CC 20 error） | **防住** | 5 函数分层解析（parseCronPart/Step/Range/Value），129 行 |
| U07 | C 度量（CC 12 warning） | **防住** | 干净通过 |
| U08 | C 度量（cognitive 31 error） | **防住** | 干净通过 |
| U10 | C 度量 ×3 | **防住** | 干净通过 |
| U09 | A 禁 API（banned-os-exec） | **防住 + 实现质变** | 见 §3 旗舰案例 |
| U04 | B 架构（layer-violation） | **未防住** | 见 §3 归因 |

**22/22 任务功能签名齐全、零 tracked 文件改动、零编译失败、-diff scorecard 协议全绿**
（aggregate：incompleteWork=0、clonedCode=0、structureViolations=0、parseErrors=0）、
反糊弄扫描 21/22 干净（T11 唯一标记经甄别为桩分类器自身的字符串匹配代码，误报）。
度量协议独立复核与记录逐条一致。

digest 本身的表现：22 个不同包（含 cmd/ 目录包）零崩溃，5 节结构稳定输出，
U05（cmd/metricgate）正确降级为 4 节（无分层归属），均价 441 token（216–836），
总注入成本 9,712 token —— 占生成成本的 0.22%。

## 3. 预防机制：两个案例说透接地在做什么

**U09（禁 API，旗舰案例）**：任务是"统计 git 提交次数"，R2 里模型 import os/exec 违反禁令。
R3 里模型**完全没有碰 os/exec**，而是组合了既有 `hotspots.Compute` API，注释写出了完整推理链：
"internal/engine 是 checker core 永不 shell out——os/exec 留给 git adapter 和 CLI；
仓库里唯一通往 `git log --numstat` 的合法出口是 internal/hotspots，复用它使数字与 `metricgate hotspots` 天然一致。"
digest 的禁令行（带 reason）+ 复用清单 + 分层契约三者合力，把实现路径从"自己 shell out"改写为"复用既有抽象"——
R1b 的"看见既有实现 = 100% 复用"在生成时复现，且是**更深的复用**（不是抄函数，是接进既有架构）。

**U04（架构，唯一漏网）**：任务要求"复用包内既有影响面分析"返回计数，
但 Count 需要"遍历文件系统建索引"这个能力，而 core 层不允许 import adapter 层——
digest 如实告知了约束（"仅允许依赖 core"），模型仍然 import 了 internal/facts。
归因：**任务设计与分层契约存在真实张力**，一行约束文本不包含解法模式
（R2 修复时模型两次都是自己发明端口-适配器才解决的）。这是"结构性修复提示"（Java 试点改进建议）的又一条证据：
digest 未来可以携带"需要跨越分层时用接口注入"的惯用法提示。

**C 类 5/5 全防的机制**：digest 的生效阈值节给出具体数字 + "超出即拆函数"指令，
模型在**生成时**就按小函数结构写——预防是免费的，修复（R2：T11 单任务 29.8 万 token）根本不会发生。

## 4. P+B 复合：终态 0/22

U04 接 R2 修复回路协议（纯 JSON 通道、防糊弄规则、规约 v1 达标判据）：

- v1 轮次（timeout 960s）：两轮均被 pi 超时杀死，烧掉 897,071 token——**harness 事故，非协议失败**（R2 已证明同任务 1 轮可修）；
- v2 续行（timeout 1800s，从 v1 中断态继续，轮次预算重开）：1 轮修复达标，1,189,246 token；
- 终态独立复核：gate exit 0、zz findings=0、五项红线+thresholdBreaches 全 0、`Count`/`ImpactCounts` 保留、
  新增 zz 文件（facts 侧 init 接线）协议合规、零 tracked 改动——又是端口-适配器终态，与 R2 殊途同归。

**P+B 复合 = 0/22 终态违规**，与 R2 的 A+B 路径终点相同，但 21/22 的任务根本没进修复环节。

## 5. 经济核算（含一个未决混杂，如实标注）

| 项 | R2 路径（A→B） | R3 路径（P→P+B） |
|---|---:|---:|
| 生成 | 2,377,996 | **4,384,090**（含重试 251,564；仅末次尝试 4,132,526） |
| 修复 | 1,715,967（7 任务） | 2,086,317（U04 单任务，含 897K 超时损耗） |
| 合计 | 4,093,963 | 6,470,407 |
| 终态违规 | 0/22 | 0/22 |
| 首过违规 | 31.8% | **4.5%** |

预注册经济端点（每千 token 违规避免数）：R2 B = 0.0041，R3 P = **0.0014 > 0** ——
高于预注册的"放弃线"（≤0），未触发放弃/调整判据，H2 弱证实。

**未决混杂（诚实标注）**：P 臂生成成本是 R2 Arm A 的 1.74×（末次尝试口径）。
三个候选成因无法在本轮拆开：① digest 诱导更多探索（U09 会话 30 次 API 调用，读了被指向的复用目标）；
② pi 早夭重试（T02/T11 各 3 次、T08 2 次）与超时事故的噪声；③ 单基线无方差数据
（R1 未记录生成 token，A 臂生成成本只有一个干净样本）。
**结论层面**：H1（违规预防）证据坚固；H2 的 token 经济学需要 A 臂同条件复跑才能定论。
**价值层面前提注意**：P 的价值不只省修复 token——21/22 任务零修复往返（省时延、省人工等待），
且 U09 型的实现质变（接进既有架构）本身不出现在任何 token 账上。

## 6. 完整性审计（防"数字好看"）

1. **早夭甄别**：定向试点 3 任务首跑空会话（provider 侧异常）→ 全量轮加入"无 zz 文件即重试"机制（≤3 次），3 任务触发重试全部成功；重试成本如实计入总账。
2. **pi=1 会话核查**：T07/T10 会话异常终止，但尾部事件确认"Successfully wrote"发生在死亡前，产物编译通过——有效。
3. **反糊弄**：22 任务 stub/TODO/空体扫描，唯一标记（T11:77 `panicArgs`）是桩分类器任务自身的检测逻辑，与 R2 审计同款误报。
4. **独立复跑**：全量度量协议重跑 22 沙箱，与 runner 记录逐条一致（仅 U04 layer+sdp）。
5. **超时事故透明化**：U04 修复的 897K token 死在 960s 窗口内，单列不隐藏，v2 从中断态续行。

## 7. 产品发现

1. **pi 供给不稳是量产 harness 的第一风险**：早夭会话（空 assistant 终态）在 7 任务试点中出现 3/7——重试机制必须内建，且"无产物 ≠ 干净通过"必须写进协议。
2. **修复超时窗口**：架构类修复的模型思考时间可超 960s；1800s 下 1 轮收敛。harness 超时应按违规类别分级。
3. **digest 全兼容目标达成**：22 包零崩溃、按包裁剪生效（441 均价 vs 全量 policy 的 10 倍以上）、provenance 可复算——非标输入兼容矩阵（清单 12 条）经受住实测。
4. **digest 可增强点**：对"任务诱导的分层张力"类场景，可携带结构惯用法提示（接口注入模式），预计能收掉 U04 型漏网。

## 8. 证据阶梯定位

| 实验 | 回答的问题 | 结论 |
|---|---|---|
| R1 基率 | 闸门拦得住吗？ | 违规率 31.8%，error 级 9.1% |
| R1b 重造 | 接地决定什么？ | 任务框架决定 0% vs 100% 复用 |
| 提示 vs 闸门 | 提示能替代闸门吗？ | 不能——提示管意图，闸门管事实 |
| R2 修复回路 | 拦下之后闭环转得动吗？ | 7/7 修复达标，JSON 通道充分 |
| **R3 前置接地** | **动手之前能少犯错吗？** | **31.8% → 4.5%；C/A 类全防；B 类兜底后终态 0/22** |

五支点闭环至此全部有量化证据：**接地（防）+ 验收（判）+ 修复（兜）**，
约束不再是"生成后等待被拦的信"，而是"生成前就进了模型工作记忆的契约"。

## 9. 诚实边界

- **单模型**：glm-5.3-flash 一族；digest 对其他模型的防护力未测。
- **同任务集第三跑**：污染对 P/A 两臂对称，但模型对任务的熟悉度本身可能随轮次变化。
- **生成通胀未归因**：1.74× 的成本增幅分不清 digest 因果与 harness 噪声，采纳前应做 A 臂同条件复跑。
- **架构类 n=1**：U04 的"未防住"与 U09 的"防住"都是单点；B 类预防力的结论待扩充任务集。
- **修复成本口径**：U04 的 2.09M 含 897K 超时损耗，有效修复成本上限 1.19M——两口径并存。
- **达标判据静态**：功能等价靠签名保留 + scorecard 计数器近似，语义等价静态不可检（范式 §6 边界不变）。

```bash
# 审计重放
# 独立复核、scorecard 聚合、签名保留检查的脚本逻辑见本报告 §2/§6，沙箱留存于 /tmp/r3-pilot/sandboxes-full/
```
