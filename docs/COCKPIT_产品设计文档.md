## 一、背景与验收结论（评审基线）

### 1.1 产品定位
metricGate Audit Cockpit 是一个**面向本机、确定性审计**的可视化驾驶舱：从本地调用记录（MCP calls）与质量检查运行（runs）识别出多个被审计项目，提供项目总览、问题分诊、质量门禁、工具活动、质量运行、规则、活动、扫描配置 9 个视图，支持按作用域（scope：全局 / 某项目 / 未归属）过滤。

### 1.2 验收结论（决定本设计优先级的证据）
1. **功能骨架齐全**：真实浏览器下首屏正确渲染 7 个项目，路由/刷新/面包屑/键盘导航可用（截图 `10-home-8899.png`）。
2. **两条 P0 阻断**：
   - **P0-A 问题分诊接口超时**：`/api/issues` 每次 30s 超时、0 字节（`.metricgate/history.db` 已 2.1GB），导致问题分诊页在真实浏览器里**恒为"0 个问题/暂无数据"且无任何错误提示**（截图 `11-issues-8899.png`）。
   - **P0-B 作用域隔离失效**：进 bugbye 项目，policy 显示 metricGate 的 `.metricgate.yaml`、calls=0、overview 顶的是全局 `✕ FAILED 运行 #1233`；面包屑显示"项目总览 › **未归属记录**"（截图 `21/22/23-*bugbye`）。
3. **P1 门禁自相矛盾**：`✕ FAILED 6 errors` 徽标与"通过/发现问题"二态状态列并置，用户看不出哪几行触发 error；go/java 两个语言块 9 项度量值一字不差。

> **一句话给管理层**：骨架工程质量过关，但问题分诊是"死的"（接口超时空态）、进项目看到的是别人的数据。**先修 P0-A、P0-B，再修 P1 门禁矛盾，然后推广。**

## 二、目标用户与场景

| 角色 | 身份 | 核心诉求（Job-to-be-done） | 高频入口 |
|---|---|---|---|
| **审计主导者**（主用户） | 在一个工作区里用 AI 编码、跑确定性检查的人 | "我这个项目现在质量如何？比上次好还是坏？哪些问题要处理？" | 项目总览 → 项目概览 → 问题分诊 |
| **配置管理者** | 维护 `.metricgate.yaml`、定义门禁与规则的人 | "当前生效的门禁条件是什么？改配置后立即生效吗？" | 扫描配置 → 质量门禁 |
| **流程复盘者** | 事后看某次检查为何通过/失败的人 | "这次运行触发了哪些规则、让步了什么？" | 质量运行 → 质量门禁 → 规则 |
| **团队协作成员**（次要） | 加入已有项目审计的人 | "这个项目有哪些历史问题、当前状态分布？" | 项目总览 → 问题分诊 |

**贯穿性用户期望**：
- **所见即所选**：点进某项目，看到的每个数字都必须是该项目的。
- **诚实**：没有数据就说"没有"，接口出错就说"出错了"，绝不拿全局数据顶替、绝不静默空态。
- **可操作**：海量数据（33 万问题）要有收敛入口，空状态要有下一步。

## 三、信息架构与导航

### 3.1 导航结构（保持现状双分组，修正入口命名）
```
侧边栏
├── 工作区（Workspace，按当前 scope）
│   ├── 项目总览      #/view=projects          列出识别到的所有项目 + 未归属
│   ├── 项目概览      #/view=overview          当前 scope 的门禁结论+评级+闸门循环+让步
│   ├── 问题分诊      #/view=issues            跨运行去重的问题列表，可流转状态
│   ├── 质量门禁      #/view=gate              当前生效条件 + 最近一次运行实测
│   ├── 工具活动      #/view=calls             本地调用轨迹
│   └── 质量运行      #/view=runs              历次运行的发现与归档
└── 审计记录（Audit Log）
    ├── 规则          #/view=rules             生效规则目录（见 P2：当前实为配置键）
    ├── 活动          #/view=activity          运行/调用/配置改动混排时间线
    └── 扫描配置      #/view=policy            配置发现链 + 生效键出处 + 保存
```
> **修正项**：`规则` 入口在规则目录接入前，文案需从"规则"改为"生效配置键"，避免用户预期规则目录却看到 138 个配置键（P2）。

### 3.2 作用域（scope）模型 —— 本设计的第一性约束
```
scope = global（全局） | project（某仓库，带 root） | unassigned（未归属）
```
**规则（全产品统一，必须写入每个视图的取数口径）**：
1. 每个视图的数据**必须**按当前 scope 过滤；跨 scope 混入 = 缺陷（P0-B）。
2. 无法归属到项目的内容**只能**出现在 `global`（合并所有项目 + 未归属）或显式命名的 `未归属记录`，**绝不能**伪装成某个项目的内容。
3. 面包屑标题必须与所选 scope 一致：进项目显示"项目总览 › **<项目名>**"，不得出现"未归属记录"（P0-B 现网 bug）。

### 3.3 视图 × 作用域 × 数据来源矩阵（反交底核对表）
| 视图 | global | project | unassigned | 数据来源端点 |
|---|---|---|---|---|
| 项目总览 | ✓（全项目+未归属） | — | ✓（仅未归属） | `/api/dashboard` |
| 项目概览 | ✓ | ✓（**须**按项目过滤） | ✓ | `/api/dashboard` + `/api/gate`(scope) |
| 问题分诊 | ✓ | ✓（**须**按项目过滤） | ✓ | `/api/issues`(scope) |
| 质量门禁 | ✓ | ✓（**须**按项目过滤） | ✓ | `/api/gate`(scope) |
| 工具活动 | ✓ | ✓（按 root 匹配） | ✓ | `/api/dashboard` calls |
| 质量运行 | ✓ | ✓（按 root 匹配） | ✓ | `/api/dashboard` runs |
| 扫描配置 | ✓（本机单例） | **待定：项目级策略** | — | `/api/policy`(scope) |
| 规则 | ✓ | ✓ | ✓ | `/api/rules`（**待接入**） |
| 活动 | ✓ | ✓ | ✓ | `/api/dashboard` timeline |

## 四、核心用户流程

### 4.1 主链路：从总览到处理问题（P0-A 修复后的目标态）
```
项目总览
  └─[点项目卡片]→ 项目概览（该项目的门禁结论/评级/趋势）
        ├─[看 FAILED 度量]→ 问题分诊（只看该项目的未处理问题）→ [点问题]→ 详情弹窗
        │        └─[流转状态]→ 未处理→已确认/误报/已接受（带确认/撤销）
        └─[改门禁阈值]→ 扫描配置 → 保存 → 立即自检(gate+measure) → 回显新值
```

### 4.2 分诊页收敛流程（解决 33 万问题不可翻）
```
问题分诊（默认：本项目 + 最新 1 次运行 + 未处理）
  ├─ 快速筛选 chips：严重度(error/warning/info) · 状态 · 规则 · 文件
  ├─ 收敛入口：「只看最近一次运行」「只看未处理」「按规则聚合」
  ├─ 列表（分页，游标翻页）
  └─ [点某条]→ 详情弹窗（描述 / 位置 / 源码窗口 / 状态流转）
```

### 4.3 慢接口与错误态流程（P0-A 配套，防"静默空态"）
```
任意数据请求发起
  ├─[进行中]→ 该视图显示骨架屏 + "读取本地数据…"（禁用刷新按钮）
  ├─[超时>阈值]→ 显式错误态：「数据读取超时，可能是本地数据库过大」+ [重试] + [查看排查指引]
  ├─[成功但为空]→ 空态：「当前范围（本项目/未处理）没有匹配的问题」+ [放宽筛选] 引导
  └─[成功有数据]→ 正常渲染
```

### 4.4 状态机：问题状态流转
```
未处理(open) ──确认──→ 已确认(confirmed) ──┬──→ 已接受(accepted)
   │                                       └──→ 未处理(open)（撤销）
   ├──标误报──→ 误报(false_positive) ──撤销──→ 未处理(open)
   └──接受────→ 已接受(accepted)
规则：①每次流转需轻确认（防误触，P2）；②有撤销入口；③按钮高亮当前态（P1：现网无高亮）。
```

## 五、逐视图原型设计（ASCII 线框 + 交互）

```

│ ◆ 项目总览 │  从本地调用记录识别仓库；无法验证归属的数据单独保留。          │

│   问题分诊 │  ┌───────────────────────────────────────────────────────┐  │
│   质量门禁 │  │ ⌘ bugbye-miserver    0 次调用·0 未通过  最近活动 —  ↗ │  │
│   工具活动 │  │ ⌘ metricGate       154 次调用·48 未通过  10/16 08:11 ↗ │  │

│ ── 审计记录│  └───────────────────────────────────────────────────────┘  │
│   规则     │  ┌─ 216 未归属调用（虚线卡片，点进 unassigned scope）─────┐  │
│   活动     │  └────────────────────────────────────────────────────────┘  │
```

**交互**：点卡片 → 进入该项目 scope（路由 `#/view=overview&scope=<root>`）。卡片需区分**有调用/仅运行/空**（P2：现网 6 空项目长得一样，进空项目是死路）。
**改造点（迭代3）**：卡片加状态徽标；空项目卡片给"查看运行/查看问题"次级入口。

### 5.2 项目概览（overview，项目 scope）—— P0-B 修复重点
**现网问题**：顶部直接顶全局 `✕ FAILED 运行 #1233` + 全局度量，该项目"质量运行=0"。

**目标态线框**：
```
┌─ 项目总览 › bugbye-miserver ───────────────────────────────┐
│  门禁结论    评级   闸门循环   让步                            │
│  ┌─ 该项目的门禁（无运行时显示空态）────────────────────┐   │
│  │  ◇ 该项目暂无质量运行                                    │   │
│  │  此项目只有工具调用数据，没有检查运行。                    │   │
│  │  [去跑一次检查]  [查看未归属运行]                          │   │
│  └──────────────────────────────────────────────────────┘   │
│  ── 评级度量（按本项目，无数据则隐藏该块）───────────────┐   │
│  │  CCG C 25   等级C · 实测触发15 · 上限25                 │   │  ← T4.4 语义区分
│  │  Fan-out 20  实测触发10 · 无 error 上限                 │   │  ← err0 改文案
│  └──────────────────────────────────────────────────────┘   │
│  ── 调用/运行统计（按本项目）──────────────────────────┐   │
│  │  调用总数 0 · 验证拦截率 — · 工具错误 0 · 质量运行 0   │   │
│  └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```
**改造点**：门禁/度量/统计严格按 scope；无运行→空态而非全局回退。

### 5.3 问题分诊（issues）—— P0-A 修复重点 + 收敛
```
┌─ 问题分诊 ────────────────────────────────────────────────┐
│  跨运行去重后的问题列表，可逐个流转状态。                    │
│  ┌ 左栏筛选 ─────────┐   收敛 chips: [只看最近运行][只看未处理]│
│  │ 全量计数  N 问题   │   ┌───────────────────────────────┐ │
│  │ 搜索 [消息/规则/文件]│   │ # 严重度 规则 文件 状态        │ │
│  │ 严重度              │   │ 1 warning X  a.go  未处理  ▾   │ │
│  │  全部 / error / ... │   │ 2 error   Y  b.go  已确认      │ │
│  │ 状态(高亮当前态)    │   │ …  分页: < 1/6718 >  (游标)    │ │
│  │  ◉未处理 ○已确认…   │   └───────────────────────────────┘ │
│  │ 规则 ▾  排序 ▾      │                                     │
│  └────────────────────┘                                     │
└─────────────────────────────────────────────────────────────┘
```
**交互**：
- 状态按钮**高亮当前态**（P1 现网无高亮）；点流转**弹轻确认**（P2 防误触）+ 可撤销。
- 点某条 → 详情弹窗（见 5.4）。
- **超时**（P0-A）：`/api/issues` 超时不静默空态，显示错误卡 + 重试 + 排查指引（history.db 过大）。
**范围行**：把陈旧 `.data/m2b-raw/...` 改为人类可读"范围：最近 N 次运行 · 本项目"。

### 5.4 问题详情弹窗（modal）
```
┌─ 问题详情 ────────────────────────────────┐
│  [warning] 规则 X · a.go:120               │
│  消息：函数 cyclomatic complexity 过高        │
│  ── 源码窗口（P3：真实数据渲染不出，需修）──┐│
│  118  func foo() {                          ││
│  119    if a { if b { if c { …              ││
│  120      ...  ← 命中行高亮                  ││
│  ── 状态 ──────────────────────────────────┐│
│  [未处理] [已确认] [误报] [已接受]           ││
└─────────────────────────────────────────────┘
```
**交互**：`Esc`/点遮罩关闭；方向键在列表移动；源码窗口命中行高亮（修复 P3 `code window rendered no lines`）。

### 5.5 质量门禁（gate）—— P1 修复重点
```
┌─ 质量门禁 ────────────────────────────────────────────────┐
│  ✕ FAILED  6 errors at or above fail_on=error   运行 #1233 │  ← 徽标三态
│  提交 5c1595c  2026/10/16 09:20:28                        │
│  ── 门禁条件  fail_on: error ──────────────────────────┐  │
│  │ 度量            阈值 实测(最差) 裕度 状态             │  │
│  │ go                                                │  │
│  │  Cyclomatic       ≤15  1112  超出1097  ●error ✕    │  │  ← error 用红，可数
│  │  Cognitive        ≤25  25   恰好压线  ○warning ⚠   │  │
│  │  File length      ≤800 298040 超出    ●error ✕    │  │
│  │  Fan-out          ≤10  20   超出10    ○warning ⚠   │  │
│  │ java（按真实语言分别取数，消除与 go 同值）            │  │
│  │  Cyclomatic       ≤15  <真实java值>  …  ○/●        │  │
│  └────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```
**改造点**：
- 徽标三态：全通过(green) / 有超阈但未达 fail_on(amber) / 未达 fail_on 失败(red)。
- 状态列区分 **error / warning / 通过**三色，并在徽标旁给"N 项 error"可定位（P1）。
- **go/java 分别取数**（P1：现网两语言块 9 项值一字不差）。

### 5.6 扫描配置（policy）
```
┌─ 扫描配置 ────────────────────────────────────────────────┐
│  发现链: ◉ .metricgate.yaml(生效) · .metricgate/config.yaml │
│           · policy.yaml                                    │
│  路径: /Users/mac/Downloads/metricGate/.metricgate.yaml     │
│  [重新读取]  [保存配置]  磁盘版本 2026/10/15 10:49           │
│  ── 分节: version gate exclude languages architecture store │
│  ── 生效键与出处: 138 个已显式设置的键                       │
└─────────────────────────────────────────────────────────────┘
```
**交互**：字段本地校验（`fail_on` 非法→"请填写 error|warning|info"）；保存→串行自检(gate+measure)→回显新值（**修复旧值不回读**，P2）；下拉切换后正确回读。

### 5.7 工具活动 / 质量运行 / 活动 / 规则（简要）
- **工具活动(calls)**：按 scope 过滤；error 结论列加 tooltip（P3）。时间统一绝对格式。
- **质量运行(runs)**：全局页合并"所有项目+未归属"或改名"未归属运行"（P2）；运行卡补"触发命令/路径"区分同提交号（P3）。
- **活动(activity)**：混排时间线；时间统一（绝对为主，可切相对）。
- **规则(rules)**：接入 `/api/rules` 出规则目录列（规则/存在理由/参数/激活位置/历史 issue 数）；未接入前入口改名"生效配置键"（P2）。

## 六、交互规范（全产品统一）

| 状态 | 规范 | 涉及 |
|---|---|---|
| **加载中** | 视图骨架屏 + 顶栏"读取本地数据…"；刷新按钮 disabled | 所有视图（现网已接线，需补超时态） |
| **超时/错误** | 显式错误卡：原因 + [重试] + [排查指引]；**禁止静默空态** | issues(P0-A) 及其它慢接口 |
| **空态** | 明确"当前范围无匹配" + 放宽筛选/下一步引导 | 项目概览(空项目)、问题分诊、空项目卡片 |
