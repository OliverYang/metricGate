# 事故卡模板（incident-to-constraint 输入）

> 用途：事故复盘报告 → metricGate 约束规则的标准化输入卡。
> 流程见 [`docs/constraints/incident-to-constraint-playbook.md`](../../docs/constraints/incident-to-constraint-playbook.md)；
> 设计出处：[`docs/design/constraint-pipeline-design.md`](../../docs/design/constraint-pipeline-design.md) §4 T1a。
> 模板只是降低提取失败率的辅助——自由文本事故同样可走流程（LLM 提取八字段 + 人确认）。

## 字段（8 项）

```markdown
## 事故卡 INC-<年份>-<序号>

- **编号/日期**：INC-2026-001 / 2026-03（复盘日期）
- **一句话现象**：<线上表现，不超过 2 行>
- **定级**：P0 资损 / P1 可用性 / P2 隐患（三选一）
- **频次**：<首次发生 / 复发 N 次 / 压测可复现>
- **根因**：<技术根因一句话，指向可判定的代码模式>
- **触发代码模式（反例）**：<能复现根因的最小代码形态，尽量给可直接粘贴的片段>
- **修复方式（正例）**：<团队确认的正确替代写法>
- **现有防回归手段**：<CR 口头把关 / IDE 提示 / 无 —— "无"或"口头"即转化信号>
```

## 填写示例（INC-2026-001）

```markdown
## 事故卡 INC-2026-001

- **编号/日期**：INC-2026-001 / 2026-03
- **一句话现象**：压测中多个定时任务吞吐互相拖垮，归档任务超时雪崩。
- **定级**：P1 可用性
- **频次**：压测可复现（2026-03 首次定位）
- **根因**：多处使用 list.parallelStream()，共享 JVM 公共 ForkJoinPool；
  一个任务阻塞（如等锁/慢 IO）会占满公共池，拖垮所有并行流任务。
- **触发代码模式（反例）**：taskList.parallelStream().forEach(...)
- **修复方式（正例）**：批量并发用自建隔离线程池
  （new ThreadPoolExecutor 显式指定队列上限与线程数，禁用 Executors 工厂，见 CONC-01）。
- **现有防回归手段**：无（代码评审口头提过，无工具拦截）
```

## 纪律

1. **单张事故卡 ≤3 条款**：只把"机械可判定的触发模式"条款化，防止事故后规则爆炸误伤；
2. **脱敏**：不写机器名 / IP / 责任人真名（用角色代称），事故卡会进入仓库长期保留；
3. **反例必须最小可粘贴**：它将直接成为 fixture 烟测用例——写不出可粘贴反例的根因，说明还没定位到代码模式，先回去补复盘。
